Run 1 vs Run 2

The only change between the two runs is the verify prompt. Run 2 reused run 1's cached extractions, so its scores differ only in the verify stage. Run 1's controls showed "changed" verdicts for wording nitpicks and for "I couldn't find that option". Run 2's prompt says a step is changed only when a viewer following it would get stuck, and only when a page found describes the new way. It also says that not finding the old option is not evidence of change.

Controls and holdout

On the 6 controls, 4 of 61 steps were marked changed, on 2 of 6 videos. Both videos are Claude products, which shipped UI changes in 2026.

  • Claude Design: "Export, not Share, for Hand off to Claude Code" (claude.com ×2): plausibly real.
  • Claude Design: Tweaks panel and Edit button. Sources are competitor and blog sites: doubtful.
  • Claude connectors: "Continue" instead of "Add" (claude.com). The button was renamed, so under run 2's own rule this should have been current: a false alarm.
Holdout (OBS, Canva, Instagram in Hindi, Facebook payouts; all 2026): 46/46 steps rated current, 46/46 with a source, 27/46 with an official source.

What these results do not show

  • Small and hand-built. 16 cases, 10 controls. One person (the build agent) chose the cases and did the hand review. Nobody independent has checked it yet.
  • Tuned on controls. The run 2 prompt was written after seeing run 1's controls. The 4 holdout videos are the only untuned precision check.
  • One run each. Gemini is not deterministic, and repeated runs may differ by a case or two.
  • Changed steps that viewers didn't report were not scored. On old videos Raahi marks about a third of steps changed, and most of those spot-checked look right (GA4 paths, Shopify Content > Menus), but this was not scored step by step.
  • Viewers can be wrong too. Two misses (Zoho, Search Console) may be region- or account-specific; Raahi cites official pages for its "current" verdict.

Source: eval/RESULTS.md.

Reproduce and raw data

Raw rows are in eval/results.json (run 2) and eval/results_v1.json (run 1) in the repo. To reproduce: python -m eval.rescue_eval --force --workers 1 --sets cases,controls,holdout_controls (needs USE_VERTEX=1 and Vertex credentials).
