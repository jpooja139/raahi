Tutorial Rescue pipeline

Paste an old YouTube tutorial. Raahi extracts the steps, checks each against current docs, and writes a comment the creator can pin. The model proposes; code decides what may be shown as fact.

Source: app/rescue.py (module docstring), docs/architecture.md section 3b.

The five stages

  1. 1. Extract Gemini watches the video at low media resolution and lists the steps with the m:ss where each is shown. If video ingestion fails, it falls back to the timed transcript. YouTube Data API supplies the real publish date and duration. Output: steps with m:ss and menu names.
  2. 2. Verify Steps go to Search-grounded calls in batches of 4, run in parallel, thinking set to low. The answer uses a fixed STEP-block format, parsed with a regex. No second LLM pass re-words it. Output: a verdict per step: current, changed or unverifiable.
  3. 3. Evidence Each step's sources come from the grounding metadata's byte-offset supports, at most 3 per step. Sources on the vendor's root domain are flagged official and listed first. Output: source chips per step.
  4. 4. Validate A current or changed verdict with no source becomes unverifiable. Timestamps past the video's end are dropped. Output: steps that may be shown as fact.
  5. 5. Update The pin-ready "what changed" comment is a template filled from sourced verdicts only. Output: the comment text.

Constants: VERIFY_BATCH=4, VERIFY_THINKING="low", VIDEO_RESOLUTION="low", MAX_SOURCES=3, MAX_STEPS=12 (app/rescue.py).

Flow

Stage 2 is drawn as three parallel batches, the 12-step maximum. Source: docs/architecture.md 3b.

Timings that appear in the sources

  • Longest job is about 90 s, inside Cloud Run's request model. docs/architecture.md section 6
  • Verify, whole tutorial: median 10.8 s. Extraction: median 21.6 s, up to 107 s for a 21-minute video (one at a time). eval results
  • Cache: a result is reused for 7 days (CACHE_DAYS). app/rescue.py

Invariants

InvariantEnforced in
A "current" or "changed" verdict with no grounding source is shown as unconfirmed.rescue.validate
Sources come from the response's grounding supports (byte offsets), never from what the model writes.rescue.sources_by_step
"Official" is a root-domain string match against the vendor's domains, not model opinion.rescue.mark_official
A timestamp past the video's real end is dropped.rescue.validate
The public update comment is a template filled from sourced verdicts. The model never writes it.rescue.update_card
A partial or failed check is never cached.rescue.analyze

Source: docs/architecture.md section 3b. In code the downgraded status is named "unverifiable"; the UI calls it unconfirmed.

What the unit tests cover

Pure helpers in tests/test_rescue.py: URL forms, timestamp parsing, ISO duration, STEP-block parsing (markdown, dashes, first verdict wins), byte offsets with Hindi text, source dedupe and cap, downgrading unsourced verdicts and bad timestamps, update-card content (English and Hindi month), step ranges, root domains, official flagging, counts. The live Gemini calls are not unit-tested.

Source: test names in tests/test_rescue.py.
