Runbook

Run locally on Vertex, redeploy safely, roll back.

Run locally on Vertex

gcloud auth application-default login   # once
USE_VERTEX=1 GCP_PROJECT=raahi-hackathon python3 -m uvicorn app.main:app --port 8000

Open http://localhost:8000. Without Vertex, copy .env.example to .env and add your own keys. Team members can run ./fetch-env.sh after gcloud login. Do not paste keys into docs or chat.

Source: README.md.

The live service

Cloud Run, region asia-south1, service raahi. It already has USE_VERTEX=1, GCP_PROJECT, GCP_LOCATION and CONTEXT_BUCKET, plus Secret Manager references for the two API keys.

Source: gcloud run services describe raahi, read 2026-10-18 (env names only; live revision raahi-00017-lbw). Runtime service account holds aiplatform.user and secret accessor only: docs/architecture.md section 1.

Warning: do not use deploy.sh for a redeploy. It uses --set-env-vars, which replaces all env vars. That would drop USE_VERTEX and the secret references.

Safe redeploy

gcloud run deploy raahi --source . --region asia-south1 --project raahi-hackathon

Do not add --set-env-vars. Existing env and secrets are kept. After deploy, check /api/health (it reports the version).

Source: Cloud Run keeps the current revision's env and secrets when a deploy passes none; README.md for /api/health.

Rollback

  • Turn off Vertex: unset USE_VERTEX. Note the architecture doc names USE_VERTEX=0. Either way the app returns to the API-key path. Grounded checks may then show steps as unverified if prepaid quota runs out.
  • Previous revision: 
    gcloud run services update-traffic raahi --to-revisions=<rev>=100 --region asia-south1
  • Secret rotation needs no code change: add a new Secret Manager version; the next revision picks it up.

Source: docs/architecture.md sections 3 and 4; README.md.
